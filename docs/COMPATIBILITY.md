# Legacy flame compatibility — 0.9.0

Opening a document, converting an entry for rendering, and exporting a normalized entry have different requirements. The document path retains the complete original file, including unsupported variations, comments, unknown namespaces, history and other entries. Its no-edit save preserves the original bytes. The renderer checks the selected entry independently; an unsupported sibling can still be preserved in the same collection. The internal `parse_flames` bulk API continues to validate all entries together.

## Producer-specific settings

Profiles use the XML producer string. The recognized prefixes are Apophysis 2.x, Apophysis 7X and Apophysis AV, case-insensitive. A 2.x string containing “3D hack” selects that branch. Untagged files retain the earlier FLAM3-style interpretation. A version selects the verified conventions below. Files using unsupported controls still receive a diagnostic.

| Setting | Recognized Apophysis | Generic / FLAM3-style |
| --- | --- | --- |
| Omitted settings | Constructor defaults include 100 × 100, scale 50, quality 50, brightness/gamma/vibrancy 1, oversample 1 and Gaussian radius 0.5. The XML reader resets an omitted gamma threshold to zero. Ordinary xforms default to weight 0 and color 0. | 100 × 100, scale 50, quality 1, brightness/gamma 4, vibrancy 1, oversample 1. Omitted radius retains the 0.2.0 box reconstruction. Transform default color alternates by input index. |
| Camera | `rotate` is degrees. `angle` is the original internal angle in radians. Reborn's rotation is −180 × angle / π. When both appear the historical parser gives `angle` precedence. | `rotate` is degrees. The reader accepts `angle` on its own; a mixed pair with no identified Apophysis producer is ambiguous. |
| Color speed | `symmetry` sets the incoming target-color weight to (1 − symmetry)/2. Classic 2.x also accepts a signed `color_speed` with this meaning. Other tagged branches use `symmetry`. | `color_speed` is a direct target-color weight; `symmetry` uses the legacy conversion. |
| Opacity and palette sampling | Ordinary opacity acts as a plot probability; the enabled final transform acts on the plotting copy. Step palette sampling uses a 255-scaled rounded index. | Ordinary opacity contributes adjusted sample mass; final opacity selects an application probability. Step/linear lookup uses the 256-scaled FLAM3 coordinate. |
| Filter and tone | Reads nonnegative Gaussian `filter` and `gamma_threshold`, with branch-specific kernel support/rounding. Packed RGB entries use byte channels, and the tagged background is quantized to whole bytes. | Accepts Gaussian `filter` / `filter_shape="gaussian"` and nonnegative `gamma_threshold`. Other kernels are blocked. |
| 4-byte packed palette | In a tagged `<palette format="RGBA">`, Apophysis skips a leading byte and uses the three following bytes as RGB. The older `<colors count="256" data="..."/>` has the same leading-byte layout. | `<palette format="RGBA">` uses trailing alpha and requires it to be 255. The old `<colors>` form uses its historical leading-byte layout. |
| Palette entries | Three-byte RGB packed palettes and complete indexed palettes (all 256 slots). An incomplete indexed palette can depend on the previous editor state and is blocked. | Packed RGB/RGBA and one or more decimal indexed RGB stops. Missing entries interpolate cyclically across the palette. |

The recognized subset supports `size`, `center`, `scale`, `zoom`, `quality`, `oversample`/`supersample`, `background`, `gamma`, `brightness`, `vibrancy`, pre- and post-affines, per-transform weights, chaos, color, final transforms and `palette_mode`. Scale is pixels per unit at the declared resolution. Six coefficients a b c d e f map (x,y) to (ax+cy+e,bx+dy+f). One `<flame>` and direct entries in `<flames>`, `<Flames>` or `<pick>` can be read. Render conversion ignores the contents of `<edit>` history and author/editor metadata; the document path still retains them.

Tagged 7X/AV files commonly write density estimator parameters alongside `enable_de="0"`, a plugin inventory, `new_linear="1"` and default color curves. The reader checks the disabled estimator configuration. M9 supports the four weighted 7X master/R/G/B curves, including the original default-point bypass and integer LUT behavior; see [COLOR_TOOLS.md](COLOR_TOOLS.md). It checks each actual transform operation, irrespective of the plugin inventory. FLAM3 3.1.1 density estimation and the verified 7X 15D internal-renderer behavior are described in [Density estimation](DENSITY_ESTIMATION.md). Active estimation from other unverified producers, multi-batch/time sampling, unknown kernels and active 3D camera controls can block conversion. A catalog index requires the corresponding external palette and is currently blocked.

## Mathematical coverage

The current registry contains 43 variations. All 15 original registry entries from Milestone 2 remain available. The following six were added in 0.3.0; the ten additions in 0.5.0 are described below and in [VARIATIONS.md](VARIATIONS.md). Use `--list-variations` to inspect the complete current registry.

| FLAM3 ID | XML name | Computation / historical controls |
| ---: | --- | --- |
| 28 | bubble | XY scaled by 1/(1+r²/4) |
| 31 | noise | Input X and Y modulate a random polar displacement with uniform radius and angle |
| 32 | julian | Integral, nonzero `julian_power` selects branch count and direction. `julian_dist` scales the radius exponent. Tagged Apophysis requires explicit power, whose original authoring default could be randomized. |
| 34 | blur | Uniform radius and angle, independent of the incoming XY point |
| 64 | foci | Exponential-pair and trigonometric mapping. The tagged path handles a zero denominator as in the 7X variation. |
| 67 | pre_blur | Displaces the affine input before any ordinary variation is evaluated. The Apophysis branch maintains four rolling radius draws per transform per orbit stream. The FLAM3 branch uses four fresh draws. |

For example, a pre-blur followed by bubble evaluates bubble on the displaced point. The order of XML attributes cannot change that stage boundary. The original x86 Apophysis and AV pre-blur use one draw for the direction and ring replacement; the 7X Pascal branch uses a separate replacement draw. Reborn's seeded generator and thread-independent batches determine the actual random sequence. Original Delphi/x87 floating-point paths and historical random streams can yield different orbits.

`var1` and vector `var` support verified numerical indices. For original 2.x the first 23 IDs (0–22) are shared with FLAM3; its eyefish/bubble/cylinder/noise/blur/pre_blur indices are 23/24/25/26/27/29. 3D hack, 7X and AV changed built-in order or loaded plugins at runtime. Named variations are required there. Mixed numbered and named definitions are rejected. Tagged Apophysis uses the source-level 1e-300 spherical denominator guard; FLAM3 uses 1e-10. A known additive `var_order` can specify ordinary term order. Unknown, incomplete or duplicated XY operations fail conversion.

The XY part of `linear3D` equals linear when no camera or transform couples Z to XY. Reborn validates those constraints, then uses the XY projection for the bundled 2.08 3D-hack artwork. In admitted 7X/AV inputs, flatten's Z-only action has no effect on projected XY. `sinusoidal_use3D="0"` is accepted; active 3D parameters remain blocked.

## Save and export

Use the document save operation to preserve a historical file. A normalized export converts one renderable entry and writes the supported model as UTF-8 XML, both affine matrices, explicit named variation weights and 256 decimal palette entries. It preserves the tagged renderer's interpretation, including signed symmetry, Gaussian radius, threshold, JuliaN parameters and non-default ordinary variation order. It can discard comments, history, author metadata, inactive parameters, degenerate Z-only terms and the collection wrapper. Historical XML readers have differing expectations for numeric precision and the shape of their source text.

## Transform editing in 0.4.0

The desktop editor uses the legacy document layer for transform changes. A coefficient, weight, color or opacity edit patches the selected opening tag. Other transforms, library members, palettes, comments and history keep their source bytes. The layer retains the document's original XML encoding. Header changes remain available on preservation-only entries. Transform operations require conversion of the selected entry to a validated render model.

Color-speed edits retain the original `symmetry` or `color_speed` spelling and apply its producer-specific numeric convention. An opacity edit updates `plotmode` for values zero and one. Intermediate opacity replaces that alias with `opacity`. Variation edits can replace an old numbered definition with named weights. The existing `linear3D` spelling is retained when its planar weight changes, and ordered AV/7X definitions receive an updated `var_order`. Adding JuliaN writes an explicit power. Unchanged numeric values preserve the original attribute spelling and precision.

New ordinary transforms are appended. Existing omitted chaos destinations continue to mean one. Duplicate appends a copy, splits the original selection weight between the two copies, duplicates the incoming chaos column, and copies the outgoing row. This keeps their combined probability equal to the original branch before subsequent edits. Reordering moves each transform's source element and remaps both axes of the transition matrix. Deleting a transform removes its outgoing row and its destination from every other row. Deletions that would leave a positive-weight transform with no reachable destination are rejected. At least one ordinary transform must remain. When an untagged source relies on implicit alternating transform colors, affected values become explicit so structural edits retain their effective colors.

Final transforms have affine, color and variation controls. They have no selection weight or chaos row. Adding a final transform to a document that already contains one, including a disabled historical definition, reports that existing definition. Every operation reindexes and validates the complete changed document before replacing the editing state. A failed operation leaves the document bytes intact. Undo and redo can restore the full document snapshot, including its original lexical details.

## Creative editing and expanded variations in 0.5.0

The added classic functions are `waves`, `fisheye`, `popcorn`, `exponential`, `power`, `cosine`, `rings`, `fan`, `eyefish` and `cylinder`. Waves, popcorn, rings and fan receive the selected transform's actual pre-affine coefficients; final transforms use their own matrix. Producer-specific formula guards and ring/fan behavior are retained. The new numerical suite compares 640 results from compiled original FLAM3 C and Apophysis 2.09 Pascal code. [VARIATIONS.md](VARIATIONS.md) lists all 31 names, producer IDs, formulas, evidence and remaining gaps.

The document layer now patches zoom, rotation, gamma, gamma threshold, brightness, vibrancy, quality, oversampling, background, filter radius and palette interpolation alongside the existing name/size/center/scale fields. It retains historical `angle` and `supersample` spellings when applicable. Clearing an explicit filter restores the source default: Gaussian radius 0.5 for recognized Apophysis inputs, box reconstruction for generic inputs. Validation rejects an invalid combined edit before replacing the original document.

Palette replacement handles packed RGB/leading-byte palettes, indexed colors, sparse generic stops and missing/catalog palettes. It writes an embedded 256-entry palette and replaces a catalog reference with `palette="-1"`; it does not resolve the missing external catalog. The operation retains the document encoding, comments and processing instructions, edit history, unrelated attributes and sibling flames. Unmodified fields retain their existing spelling and precision. Palette gamma/contrast adjustments are baked into the stored colors. M9 separately implements non-default legacy reconstruction `curves` and an explicitly identified continuous curve mode.

Appending a generated flame validates its model and adds a collection wrapper when the original file contains one standalone flame, retaining that original element's bytes. Duplicating an entry also preserves unsupported source fields. Deletion retains at least one flame. Collection changes and accepted creative edits restore source bytes and the selected entry through undo/redo. Applying a mutation to the current flame patches its supported fields while retaining its original name and unrelated XML; saving a branch appends its chosen ancestry as separate entries.

The seeded random and mutation algorithms are new Reborn workflows and do not reproduce historical random streams. GPL palette exchange uses RGB8, while embedded palette entries can retain fractional channels. At the original M5 checkpoint, broader palette formats/catalogs, alpha output, density estimation and non-default historical curves remained open. M7 added alpha output, M8 added UGR/MAP exchange and M9 added weighted tone curves, M11 completed the named starting variations and M12 added the FLAM3 density estimator. See [CREATIVE_TOOLS.md](CREATIVE_TOOLS.md) for the exact controls and save behavior.

## Vulkan compatibility in 0.6.0

Vulkan adds a rendering choice without changing the XML model, producer detection or source-preserving save contract. The shader covers all 43 current variation names and the admitted generic/classic/7X/AV conventions. The ordinary CPU renderer retains its double calculations, MT19937-64 stream and earlier image/reference tests. The CLI still defaults to that CPU path. New saved editor preferences select Automatic with CPU fallback; backend/device preferences are machine settings and are not inserted into legacy flames.

The compute path has a narrower numeric and resource envelope than the CPU. It accepts up to 64 ordinary transforms plus a final transform. Packed nonzero inputs must remain finite, nonzero and normal in FP32; selection intervals must survive cumulative-boundary conversion and be at least `2^-24`. JuliaN power, camera dimensions, histogram addressing and selected-device storage limits have explicit bounds. Historical waves/rings/fan denominators require additional checks because the original `1e-300` guards cannot be represented in FP32. [GPU_KERNEL.md](GPU_KERNEL.md) defines these limits and the special zero-radius behavior.

Unsupported compute inputs remain valid CPU models when they meet the existing CPU rules. With fallback enabled, the actual result reports CPU and the reason for leaving Vulkan; strict Vulkan requests report an error. Missing loaders, unavailable devices and applicable compute allocation/capability failures follow the same policy. Invalid flame settings, invalid sample counts, host-buffer limits and cancellation are not hidden by fallback. A preserve-only legacy entry remains preserve-only: enabling a GPU does not implement missing variations or previously blocked historical controls.

The Vulkan sampler uses FP32 and a different portable random stream with 256-sample chains. Equal seeds across ordinary CPU and Vulkan renders do not promise equal pixels. A separate double CPU reference using the compute stream supports numerical comparison. The tested image fixtures and all-variation probes are described in [GPU_TESTING.md](GPU_TESTING.md); they establish the stated limits on llvmpipe software Vulkan, not universal driver or historical-application equivalence. Physical-GPU execution and Windows-driver acceptance remain pending. CUDA, tiled 16K output and high-bit-depth export are not supplied by this compatibility increment. See [GPU_RENDERING.md](GPU_RENDERING.md) and [WINDOWS_GPU.md](WINDOWS_GPU.md).

## Streamed export and queue compatibility in 0.7.0

The file renderer retains the ordinary CPU batch seeds, orbit math and global camera. Opaque RGB8 strip reconstruction is tested against the earlier dense implementation across generic and tagged 2.09/7X models, box/Gaussian filtering, opacity, rotation, pre-blur and final transforms. Existing original-producer pixel and numerical tests remain required. BMP file bytes now use a top-down negative-height layout; decoded orientation and channels remain unchanged. The earlier direct `write_image` API keeps its bottom-up representation.

Sixteen-bit integer output and straight alpha have explicit new reconstruction/export semantics in [IMAGE_FORMATS.md](IMAGE_FORMATS.md). They do not claim byte equivalence with historical high-depth or transparent exporters. The mathematical CPU model, source-preserving XML behavior and registry of supported variations are unchanged. Queue snapshots serialize the model and explicitly retain per-transform and final-transform source math flags, including conventions not represented by ordinary XML fields.

Restart data are internal engine state. Resume binds the effective model, sample budget, seed, backend policy, image format, engine/compiler/platform and, after committed GPU sampling, device/driver/shader identity. It is not a cross-version or cross-device archival format. Worker counts and resource budgets may change when the saved geometry still fits. This M7 record preceded the M8 interfaces described below; full historical interpreter/binary-plugin coverage and broader original-application audits remain open. [High-resolution guide](HIGH_RES_RENDERING.md) · [Verification](HIGH_RES_ACCEPTANCE.md)

## Extended compatibility in 0.8.0

Modern Lua and legacy Pascal scripts share a private working-document transaction. The legacy parser implements the explicitly listed subset in [LEGACY_SCRIPTING.md](LEGACY_SCRIPTING.md), including source-checked affine and coordinate semantics. Unsupported grammar/APIs fail before active-document application. Deterministic seeds describe the Reborn stream, not a claim of historical RNG-sequence equivalence. The Lua runtime and its permitted API are documented in [SCRIPTING.md](SCRIPTING.md).

Native variation modules use the new 64-bit C ABI. Historical plugin source conventions were audited, and a migration example is included; old 32-bit DLLs are not loaded. Module descriptors and parameter ranges are validated, source saves retain identity/version and parameter values, and missing modules leave XML preserve-only. Native callbacks execute trusted code in-process; invalid memory accesses and non-returning functions cannot be safely recovered by the host. Binary approvals, queue identity and checkpoint identity are distinct from portable source-format identity. [Plugin contract](PLUGINS.md)

UGR import is checked against all 256 colors produced by original Apophysis Pascal gradient routines; MAP preserves the supported RGB8 palette contract. UPR is limited to the identified `mt.ufm/mt-pixel` and Apophysis flame-coloring formulas, with explicit rejection of incompatible layers/parameters and explicit warnings about renderer differences and palette quantization. No Ultra Fractal renderer pixel oracle has been executed. [Format fixtures and limitations](LEGACY_FORMATS.md)

Native `.apoproject` files retain the exact legacy source collection inside a bounded, versioned XML envelope. Unknown envelope data, metadata and opaque future animation data survive supported edits. The project adds settings/presets/references rather than changing legacy rendering semantics. For projects without animation, saving explicitly to a legacy file extracts the collection and omits the native envelope. M9 blocks that save when an animation payload exists; Export flame library writes a separate collection copy. [Project format](PROJECT_FORMAT.md)

## Animation and color in 0.9.0

The native animation evaluator uses explicit stable transform IDs, exact keyframe endpoints, bounded continuous interpolation and hold cuts. Timed legacy import requires the user to choose frame or second interpretation. These rules do not claim historical 2.x/7X/AV animation-interpreter equivalence. Keyframe snapshots retain exact source collections; unknown animation payloads remain opaque. [Model](ANIMATION_MODEL.md) · [Morphing](MORPHING.md)

The 7X tone-curve implementation is checked against the unchanged pinned Pascal rational Bézier routine and original default-bypass/LUT/rounding expressions. All 5,397 integer outputs in the checked oracle match; 7,196 raw samples agree within 2e-15. A modern mode explicitly solves the continuous curve by X and uses its own serialized marker. These modes are distinct and cannot be continuously interpolated across a segment; use a hold cut or choose one mode for both endpoints. Identity curves leave prior renderer pixels unchanged. [Color tools and provenance](COLOR_TOOLS.md)

Direct-color variation families, active 3D rendering/camera controls, unsupported estimator profiles, motion-blur time sampling and unimplemented historical variations remain unsupported for rendering. Their source data continue to be preserved.
