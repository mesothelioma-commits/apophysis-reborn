# CPU flame rendering in 0.2.0

**Transform evaluation.** XML `coefs="a b c d e f"` maps a point to `(ax + cy + e, bx + dy + f)`. All enabled variation terms receive that same pre-affine point. Signed term weights scale their contributions. The post-affine transform acts on the sum. The scalar color coordinate moves by `color_speed * (transform_color - old_color)`. Destination probability comes from its base weight times the previous transform's outgoing chaos multiplier. A missing multiplier equals one.

**Registry.** The CPU implements FLAM3 IDs 0 through 14 in order: linear, sinusoidal, spherical, swirl, horseshoe, polar, handkerchief, heart, disc, spiral, hyperbolic, diamond, ex, julia and bent. Each accepts a variation weight. These historical IDs have no additional user parameters. Julia draws one branch bit from the Reborn sampler. Historical polar formulas in this range use atan2(x,y) where specified. The reference suite checks all 15, both Julia branches, signed weights and the affine conventions. Additional IDs and parametric families belong in later compatibility work.

**Plotting.** Each iteration advances the persistent orbit with an ordinary transform. A final transform, when present, acts on a plotting copy with the final transform's opacity as its application probability. The ordinary transform sets sample visibility through the historical logarithmic opacity convention, for example 0.5 contributes 0.1 of a full hit. The camera rotates around the flame center and projects using scale × 2^zoom. Increasing source Y goes down the output raster before rotation. Palette lookup uses the 256-entry coordinate convention, clamps at the last color, and supports step and linear sampling.

**Exposure.** The default sample budget is the ceiling of quality × width × height × 2^(2 × zoom), with a minimum of one. An explicit iteration budget overrides this. Each spatial bin accumulates source RGB and opacity with 24 fractional bits of effective precision (unit value 16,777,215). Per-bin logarithmic density accounts for camera scale and sample count. A box filter combines the oversampled bins in linear light before the exposure passes through gamma and vibrancy controls. Background is composited before conversion to RGB8. The renderer reports requested samples, hits in frame and non-finite steps; repeated singular inputs can consume iterations without producing hits.

**Historical differences.** Reborn uses mt19937_64 with a defined conversion to a 53-bit uniform number, batch-specific seeds and cumulative probability tables. FLAM3 uses ISAAC and a quantized transform table. The modern CPU output also differs in filtering, gamma threshold, highlight handling, quantization, and how non-finite orbits restart. FLAM3's adaptive density estimation, full historical filter family and animation timing are outstanding. The numeric and image reference reports identify which comparisons currently pass.

**Size and memory.** A dense subpixel histogram costs 32 × width × height × oversample² bytes, plus output/worker storage. The default buffer budget is 512 MiB. A 16,384² image at oversample 1 alone would need 8 GiB for these histogram bins. Genuine 16K acceptance requires the separate high-resolution milestone and its decode, memory, responsiveness, cancellation and seam checks.

**Output.** P6 PPM stores top-down RGB. RGB24 BMP stores padded bottom-up BGR rows. The output is staged beside its destination and renamed after writing finishes. The bundled PNG preview is a lossless conversion of the engine's BMP. GPU rendering, high-bit-depth output and transparent export remain future work.
