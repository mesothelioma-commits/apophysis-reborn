# CPU flame rendering

**Transform evaluation.** XML `coefs="a b c d e f"` maps a point to `(ax + cy + e, bx + dy + f)`. The pre-affine matrix acts first. If enabled, pre_blur displaces that point before the ordinary variation terms receive it. Signed term weights scale their contributions. The post-affine transform acts on the sum. The scalar color coordinate moves by `color_speed * (transform_color - old_color)`. Destination probability comes from its base weight times the previous transform's outgoing chaos multiplier. A missing multiplier equals one.

**Original registry.** The CPU implements FLAM3 IDs 0 through 14 in order: linear, sinusoidal, spherical, swirl, horseshoe, polar, handkerchief, heart, disc, spiral, hyperbolic, diamond, ex, julia and bent. Each accepts a variation weight. These historical IDs have no additional user parameters. Julia draws one branch bit from the Reborn sampler. Historical polar formulas in this range use atan2(x,y) where specified. The reference suite checks all 15, both Julia branches, signed weights and the affine conventions. Additional historical IDs and their parameter conventions appear in COMPATIBILITY.md.

**Plotting.** Each iteration advances the persistent orbit with an ordinary transform. A final transform, when present, acts on a plotting copy with the final transform's opacity as its application probability. For an untagged input, the ordinary transform sets sample visibility through the FLAM3 logarithmic opacity convention. A value of 0.5 contributes 0.1 of a full hit. The camera rotates around the flame center and projects using scale × 2^zoom. Increasing source Y goes down the output raster before rotation. Palette lookup uses the 256-entry coordinate convention, clamps at the last color, and supports step and linear sampling.

**Exposure.** The default sample budget is the ceiling of quality × width × height × 2^(2 × zoom), with a minimum of one. An explicit iteration budget overrides this. Each spatial bin accumulates source RGB and opacity with 24 fractional bits of effective precision (unit value 16,777,215). Per-bin logarithmic density accounts for camera scale and sample count. Spatial filtering combines the oversampled bins before the exposure passes through gamma and vibrancy controls. Background is composited before conversion to RGB8. The renderer reports requested samples, hits in frame and non-finite steps; repeated singular inputs can consume iterations without producing hits.

**Tagged Apophysis inputs in 0.3.0.** Recognized producer versions enable branch-specific transform conventions, nearest 255-scaled palette indices in step mode, quantized RGB buckets with a white level of 200, probabilistic ordinary-transform opacity and enabled final transforms. The Gaussian spatial kernel uses cutoff 1.8 and a truncated support diameter for tagged Apophysis inputs. FLAM3-style Gaussian inputs use cutoff 1.5 and retain the fractional diameter. Both support parity-correct subpixel placement and a histogram gutter. The gamma threshold blends the low-density response into regular gamma. Untagged inputs from 0.2.0 without an explicit radius retain box reconstruction. Historical integer-background compositing and vibrancy quantization are tested against original Pascal RGB results. See PRODUCER_ORACLE.md.

**Historical differences.** Reborn uses mt19937_64 with a defined conversion to a 53-bit uniform number, batch-specific seeds and cumulative probability tables. FLAM3 uses ISAAC and a quantized transform table. Other differences include density estimation, highlight handling, the precise sampling sequence and how non-finite orbits restart. FLAM3's adaptive density estimation, full historical filter family and animation timing are outstanding. The numeric and image reference reports identify which comparisons currently pass.

**Size and memory.** A dense subpixel histogram costs 32 × width × height × oversample² bytes, plus filter gutters, output/worker storage and kernel weights. The default buffer budget is 512 MiB. A 16,384² image at oversample 1 alone would need 8 GiB for these histogram bins. Genuine 16K acceptance requires the separate high-resolution milestone and its decode, memory, responsiveness, cancellation and seam checks.

**Output.** P6 PPM stores top-down RGB. RGB24 BMP stores padded bottom-up BGR rows. The output is staged beside its destination and renamed after writing finishes. The bundled PNG preview is a lossless conversion of the engine's BMP. GPU rendering, high-bit-depth output and transparent export remain future work.


**Editor preview.** The primary editor fits a model copy to its viewport and uses oversample one for interaction. It renders successive deterministic passes at increasing sample budgets. The largest pass replaces the earlier image. A stop token cancels obsolete jobs, including spatial reconstruction. The full-resolution file render uses the saved output dimensions and oversample value with a separately chosen sample and memory budget.

**Cancellation and progress.** Existing synchronous render callers retain their behavior. Optional cancellation throws `RenderCancelled`; optional progress reports completed requested samples after merged work batches. File output checks cancellation while encoding rows and before the staged file replaces its destination.
