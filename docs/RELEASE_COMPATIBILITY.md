# Release compatibility report — 0.10.0

## Release decision

**0.10.0 is a release-hardening checkpoint, not a declaration of complete Apophysis 2.x/7X/AV parity or a 1.0 release.** The native editor, renderer, source-preserving files, creative tools, Vulkan implementation, large-image pipeline, scripting/plugins and animation workflows are real implementations. The original brief also requires capabilities that remain missing. Completing Milestone 10’s packaging and documentation work does not waive those requirements.

This report reconciles the original 25-section project brief with the actual supported surface. It complements [COMPATIBILITY.md](COMPATIBILITY.md), which defines exact file/mathematical behavior, and [TEST_PLAN.md](TEST_PLAN.md), which records executed release gates. The machine-readable companion [requirements-status.json](requirements-status.json) retains stable requirement IDs, source-section references, evidence paths and the SHA-256 of the original brief. Grouped rows and repeated requirements are not a weighted completion percentage.

| Status | Meaning |
| --- | --- |
| Delivered | Working code and evidence exist for the bounded behavior stated in that row. This does not override separate platform limits. |
| Partial | An implemented subset exists; the stated remainder still belongs to the project scope. |
| Missing | The requested capability is not implemented in this checkpoint. |
| Platform unverified | Code or binaries exist, but the required target-system execution has not established acceptance. |

## Practical compatibility boundaries

**Opening, preserving, rendering and exporting are separate operations.** A preservation-only entry can retain unknown parameters and still be saved without being renderable. A canonical selected-flame export writes the supported model and can omit source comments/history; it is not the same operation as source-preserving Save. A `.apoproject` adds native settings/timeline data and is not an old Apophysis file format. Modern curve markers and exact native-plugin hashes have their own portability boundaries.

**31 built-in variations are implemented.** The brief’s explicitly named starting list contains 40 variations: 28 are implemented and 12 remain absent. The additional implemented names are `noise`, `foci` and `pre_blur`. The missing named functions are `blob`, `pdj`, `fan2`, `rings2`, `perspective`, `juliascope`, `gaussian_blur`, `radial_blur`, `pie`, `ngon`, `curl` and `rectangles`. This starting list was expressly non-exhaustive; completing those 12 would not, by itself, complete the historical variation inventory.

**Windows and physical GPU acceptance are separate from compilation.** Current available-host results, exact executable identities and benchmark settings are in the release verification records. The Vulkan evidence from the existing host uses software Vulkan. A successful Linux test, PE import audit or Wine observation is not a Windows 11 UI/driver test or a physical-GPU benchmark.

**Full 16K evidence has a named source revision.** The retained M7 image was genuinely sampled at 16384×16384, decoded completely by independent paths, compared across strip/queue resume workflows and measured for memory/UI responsiveness. That is historical M7 acceptance, not an invented new 0.10.0 timing. Any new large case must retain its own build/device identity and results. See [HIGH_RES_ACCEPTANCE.md](HIGH_RES_ACCEPTANCE.md).

## Work that remains before a full-parity release

1. **Complete the historical inventory and missing mathematics.** Audit the remaining built-ins/plugins against pinned original source; implement the twelve named omissions and the wider verified inventory with parameter/default/order/RNG cases, CPU reference results, GPU admission and example flames. Add active density estimation, the required filter families, 3D/direct-color behavior and other presently blocked source settings. Do not treat a successful import as support for these calculations.
2. **Close export and metadata gaps.** Add the requested JPEG, WebP and OpenEXR/HDR encoders with independent decode/precision/alpha tests, then define color management, compression controls, embedded flame metadata and sidecar workflows. A Qt decoder alone is insufficient.
3. **Complete creative/editor preferences and historical workflows.** Add persistent per-transform locks and multi-selection/synchronization, light theme, named/classic workspaces and shortcut profiles, broader preference categories and configurable recovery/storage behavior. Reconcile each original control’s purpose and defaults before marking a replacement complete.
4. **Extend language and animation compatibility.** Broaden the documented legacy script API with original-source fixtures; add explicit timeline/curve scripting, historical animation profiles and missing track/motion sampling where required. Preserve the current source, plugin identity and checkpoint contracts.
5. **Execute target-platform and lifecycle acceptance.** Test Windows 11 install/launch/upgrade/uninstall, high-DPI/multi-monitor behavior and physical NVIDIA/AMD/Intel devices. Record actual device/driver/build identity, strict-backend results and measured performance. Complete original-application reopen/render comparisons for the supported export profiles.
6. **Harden remaining failure boundaries.** Decide and implement native-plugin process isolation and local crash reporting if feasible; test actual faults, disk-full/permission failures and driver loss without corrupting prior projects, queue state or completed outputs.

These are continuation requirements, not a list of features silently removed from the original brief.
